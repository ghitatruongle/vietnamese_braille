Viet Braille App

Tài liệu lịch sử: cấu trúc file bên dưới có thể không còn khớp implementation. Xem README và docs/architecture.md. Ứng dụng Flutter chuyển đổi văn bản tiếng Việt sang Unicode Braille 6 chấm và BRF, hỗ trợ chọn tệp, trích xuất nội dung từ nhiều định dạng, OCR ảnh và xuất kết quả để chia sẻ. Mục tiêu của tài liệu này là thống nhất kiến trúc, interface và quy tắc phát triển để nhiều AI có thể làm việc song song mà không xung đột.

Module và trách nhiệm

  • core: chứa quy tắc nền tảng, contract mapping ký tự tiếng Việt sang Braille Unicode.
  • data: chịu trách nhiệm đọc tệp, OCR ảnh, chọn tệp và xuất/chia sẻ tệp BRF.
  • domain: định nghĩa nghiệp vụ chuyển đổi tiếng Việt sang Braille và định dạng BRF.
  • presentation: UI, state management, provider, screen và widget tái sử dụng.

Interface chi tiết

core/braille_mapping.dart

Chịu trách nhiệm chuẩn hóa chuỗi đầu vào và ánh xạ từng ký tự sang mã Braille Unicode.

abstract class BrailleMapping {
  String? mapChar(String char);
  String normalize(String text);
}
  • String? mapChar(String char): trả về chuỗi Unicode Braille 6 chấm (U+2800–U+283F) tương ứng với một ký tự đã được chuẩn hóa; trả về null nếu không hỗ trợ.
  • String normalize(String text): chuẩn hóa Unicode NFC, chuyển chữ thường và áp dụng tiền xử lý tiếng Việt trước khi map.

data/text_extractor.dart

Contract trích xuất văn bản từ tệp đầu vào theo MIME type.

abstract class TextExtractor {
  Future<String> extractText(String path, String mimeType);
}
  • Các implementation hiện tại: TXT, DOCX.
  • Phải bắt lỗi async đầy đủ và trả lỗi có ý nghĩa cho tầng trên.

data/ocr_processor.dart

Contract nhận dạng chữ từ ảnh khi người dùng chọn ảnh thay vì tài liệu văn bản.

abstract class OcrProcessor {
  Future<String> recognizeImage(String path);
}

data/file_picker_service.dart

Dịch vụ chọn tệp đa nền tảng. Kết quả phải mang đủ đường dẫn và MIME type để tầng data xử lý.

class FilePickResult {
  String path;
  String mimeType;
}

class FilePickerService {
  Future<FilePickResult?> pickFile();
}
  • pickFile(): trả về null khi người dùng hủy chọn tệp.
  • Windows dùng file picker bình thường; Android cần xử lý quyền theo package được chọn nếu có.

data/file_exporter.dart

Dịch vụ ghi nội dung BRF tạm thời và chia sẻ ra ngoài ứng dụng.

class FileExporter {
  Future<String> saveTemp(String content);
  Future<void> share(String path);
}
  • saveTemp(String content): lưu tạm nội dung BRF, trả về đường dẫn tệp đã tạo.
  • share(String path): chia sẻ tệp theo đường dẫn được cung cấp.

domain/braille_converter.dart

Contract nghiệp vụ chính để chuyển văn bản tiếng Việt sang biểu diễn Braille Unicode.

abstract class BrailleConverter {
  String convert(String text);
}

domain/brf_formatter.dart

Contract định dạng Braille Unicode thành nội dung BRF hợp lệ với giới hạn độ dài dòng.

abstract class BrfFormatter {
  String format(String braille, {int lineLength = 40});
}
  • Mặc định mỗi dòng tối đa 40 ký tự, nhưng cho phép cấu hình.
  • Đầu ra BRF chứa North American Braille ASCII và các ký tự điều khiển bố cục.

presentation/providers/conversion_provider.dart

Placeholder cho state management bằng Riverpod. AI phụ trách UI/state sẽ hiện thực sau.

presentation/screens/home_screen.dart

Placeholder cho màn hình chính của ứng dụng.

presentation/widgets/

Để trống ở giai đoạn khởi tạo. Các widget dùng chung sẽ được thêm dần trong các tác vụ sau.

Quy tắc bắt buộc

  • Luôn dùng UTF-8 cho mã nguồn, tài liệu và dữ liệu văn bản.
  • Toàn bộ code phải dùng null safety.
  • Mọi xử lý bất đồng bộ phải dùng async/await và bắt lỗi đầy đủ.
  • Text tiếng Việt phải được chuẩn hóa Unicode NFC và chuyển thành chữ thường trước khi mapping.
  • Logic normalize phải ưu tiên lowercase + NFC trước khi chuyển từng ký tự sang Braille.
  • Text từ file/OCR phải được trim trước khi chuyển đổi.
  • Unicode Braille hiển thị dùng các mẫu 6 chấm U+2800–U+283F; BRF dùng Braille ASCII.
  • Mỗi dòng trong BRF tối đa 40 ký tự, có thể cấu hình qua tham số lineLength.
  • Không đưa logic UI vào domain/data; giữ phân tách tầng rõ ràng.
  • Các interface trong tài liệu này là hợp đồng chung; AI khác không tự ý đổi chữ ký phương thức nếu chưa thống nhất.

Lưu ý nền tảng

  • Android: nếu dùng OCR từ camera hoặc ảnh chụp trực tiếp, cần khai báo quyền CAMERA trong AndroidManifest. Không cần quyền INTERNET cho phạm vi hiện tại.
  • Windows: dùng file picker bình thường, không cần cấu hình quyền đặc biệt cho chọn tệp cục bộ.

Phụ lục: Bảng mapping Braille tiếng Việt đầy đủ

Mapping sử dụng Unicode Braille 6 chấm (U+2800–U+283F). Dấu thanh là ô Braille riêng biệt đặt TRƯỚC nguyên âm. Chữ số có tiền tố number-indicator. Định hướng mapping:

a->a, b->b, c->c, d->d, e->e, f->f, g->g, h->h, i->i, j->j, k->k, l->l, m->m,
n->n, o->o, p->p, q->q, r->r, s->s, t->t, u->u, v->v, w->w, x->x, y->y, z->z.
á->/a, à->?a, ả->.a, ã->*a, ạ->>a (tương tự e, i, o, u, y)
ă->(a, ắ->/(a, ... (đầy đủ tổ hợp)
â->^a, ấ->/^a, ...
ê->^e, ...
ô->^o, ...
ơ->[o, ...
ư->[u, ...
đ->=d
Các dấu câu giữ nguyên hoặc bỏ qua giai đoạn đầu.
